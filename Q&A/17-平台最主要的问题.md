# 平台最主要的问题是什么

**问：** 目前这套平台最主要的问题是什么？

## 答

### 结论

**最主要的问题是：平台处在「新旧架构未完成迁移」的过渡期——两套 DWB 并行、四类威胁指标（MD5/域名/URL/IP）在任一条链路上都不完整，下游该查哪张表、口径是否一致尚未闭环；再叠加底层 HCI 磁盘不稳定带来的任务中断风险。**

若只选一个根因：**数据架构与口径未统一**，其余问题多由此衍生或放大。

### 1. 架构过渡期（文档记载的核心问题）

| 现象 | 影响 |
|------|------|
| 新旧两套 DWB 并存（`default.dwb_*` vs `sodl.dwb_sodl_*`） | 统计口径可能不一致 |
| `dwb_sodl_url_info` 已暂停 | 新链路缺 URL DWB |
| 旧链路 audit 路径无 IP DWB；旧 `dw_ip_info` 等已注释 | 旧链路缺 IP DWB |
| 下游分别用哪些表文档未回答 | 改表/停任务影响面不清 |

当前四类 DWB 缺口：

```text
新链路：MD5 ✅  域名 ✅  URL ❌  IP ✅
旧链路：MD5 ✅  域名 ✅  URL ✅  IP ❌
```

### 2. 稳定性（生产侧突出的外部冲击）

- 2026 年 5/6 月磁盘拔插 8、10 次，处于近期高位
- 与 5/25 大数据任务全部暂停、6/11 HCI 磁盘损坏直接相关

### 3. 口径与覆盖的次级问题

- `domain_info` 非全量域名，易被误用
- `topthreat` 文件统计未纳入 SODL 日志
- 新旧链路维表关联逻辑是否一致待确认

### 4. 可观测与运营

- `create_hive_partition` 失败仍到 End，分区问题延迟暴露
- 23 条运营诉求多为手工/临时脚本，强依赖旧链路 audit 表

### 5. 治理与文档缺口

整改方案、负责人、排期、监控 SLA 在设计说明中明确暂不展开；历史问题详细记录在设计里引用但仓库可能不完整。

### 问题优先级（归纳）

```text
P0  新旧 DWB 并存 + 四类指标拆分在两套链路上
P1  HCI/磁盘故障 → 任务暂停、运维占大量精力
P2  统计口径不统一（topthreat vs DWB、domain 窄表误用）
P3  分区失败静默、手工运营、工程治理
```

**推断：** P0–P3 优先级为根据文档问题表、换盘事件和运营依赖频率归纳的排序，原文未写「最主要」三字。
