## 2. 分项差距与原因

### 2.1 体裁：从「三件事说明」扩成「验收包」

| | 内容 |
|--|------|
| **预期** | v1 §1：只回答怎么用、痛在哪、要什么体验/指标（L12–16） |
| **v3** | 新增 §0 阅读指引、§5.4 G 过关线、§5.5 指标—诉求—验收方法、§8 七项待回复 |
| **原因** | copy 2 已引入「提交方/接收方/验收原则」结构；本次改写沿该模板继续加厚，未询问是否需要「对外简版 vs 验收详版」 |
| **待你确认** | 过关线、对照表是要保留还是移到单独《验收附件》 |

---

### 2.2 技术细节渗入正文（违背使用方边界）

| | 内容 |
|--|------|
| **预期** | v1 L6–7：不涉及底层技术选型、组件设计；痛点用业务语言（O-1「不用先选 Hive 表」） |
| **v3 示例** | §2.3 写 Oozie 任务时刻；§3.1 写 `default.dwb_md5_info`；§3.2 写 `csc.ods_csc_log_audit`；§5 写调度背景；附录 B「底层任务」列 |
| **原因** | ① 指令点名 `log/DATA_FLOW.md`；② 为证明「有据」大量引用表名/任务名；③ Q&A/16 本身用表名对照，被整段搬进正文 |
| **改稿方向** | 正文只保留「审计类 / 旧链路宽表 / 新链路宽表」；表名、任务名仅附录 B 留空给建设方填 |

### 2.3 「具体场景」被写成过长叙事

| | 内容 |
|--|------|
| **预期** | 指令：具体使用场景 + 具体痛点；v1 用 O-1～O-5 表格即可 |
| **v3** | §3.1–3.5 各含「我要做什么 / 现在怎么做 / 痛点表 / 我们要求的体验」；§7 张孜颖上午时间线 |
| **原因** | 将「场景化」等同于 user story + 一日剧本；brainstorming skill 要求探索意图，但生成时未先出大纲确认详略 |
| **待你确认** | 保留 §3 精简版（每场景 5 行）还是删除 §7 |

---

### 2.4 性能指标：有数无据

| | 内容 |
|--|------|
| **预期** | 指令要「具体性能指标」 |
| **v3** | P-1 P95≤15min、P-3≤8min 等；§2.5 声明「材料未系统统计」 |
| **原因** | 数字继承 v1/copy2，非从 `log/` 或 xlsx 测算；`log/` 仅有调度时刻（00:30、02:30），**推不出** P95，模型仍保留数字并加「基线待建」免责 |
| **差距** | 「具体」被满足为**具体目标值**，而非**有测量依据的具体现状+目标** |
| **改稿方向** | 要么删 P50/P95 只留体验要求（进度、超时提示）；要么明确写「以下为目标提议，上线前 jointly 定基线」 |
