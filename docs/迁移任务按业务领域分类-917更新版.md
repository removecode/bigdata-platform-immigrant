# 迁移任务按业务领域分类（917更新版）

更新日期：2026-09-21  
基线材料：《大数据平台YARN上的任务梳理-云脑大数据平台-917梳理.csv》

## 一、更新结论

917材料仍为45项去重服务，任务总数没有变化，但有15项服务的标注状态发生变化。本版以917材料为最新盘点基线，同时保留已有用户决策的更高优先级。

| 服务级状态 | 数量 | 说明 |
|---|---:|---|
| 纯保留 | 25 | 服务下未出现其他状态 |
| 纯可下线 | 11 | 材料标注为可下线，不等于已批准或已停服 |
| 纯待确认 | 4 | 需业务方确认去留 |
| 纯已下线 | 3 | 材料标注已下线，仍需核对现网实例和共享依赖 |
| 混合状态 | 2 | `soapa-logger-stream-prc`、`log_compress`的子任务/调度实例状态不一致 |
| 合计 | 45 | 同一服务的多条SQL和子任务合并计1项 |

45项中有16项服务存在至少一个“可下线/已下线”标记，但不能直接得出“已减少16项迁移任务”。其中纯已下线3项；`phishing-url-operation-prc`另有DEC-004的用户确认下线决策；其余仍应先核对使用方、依赖和执行窗口。

## 五、迁移计划口径如何调整

1. 立即将纯可下线11项从“确定改造队列”移入“业务去留与退出验证队列”，但在批准前不从总盘点删除。
2. `soapa-logger-stream-prc`和`log_compress`必须精确到子任务/调度实例，禁止按服务名整体停用。
3. `sync-mongo2hive-job`、`datax-server`、`secevent-to-hive-stream-prc`属于“旧接入服务可退”，不是“对应数据不需要”。新供数的表、历史、增量、时效和下游验收完成前，不得退旧链路。
4. `cert-app-samplesync-job`、`ti-ip-detection-send-prc`、`ti-hot-data-detection-fusing-prc`由保留降为待确认，应在锁定正式迁移数量前完成业务签字。
5. `domain-heat-stats-cron-job`由待确认改为保留，应纳入热度库批次，补齐依赖和验收SLA。

## 六、证据边界

- 917表中的“可下线”是盘点状态，本文不将其自动升格为已批准决策或已完成操作。
- 任务状态是按服务去重后统计；子任务不同状态必须保留，不用服务首行状态覆盖。
- 原材料没有提供每个“可下线”项的正式审批人、实施日期、共享依赖核查和现网停调度证据，这些均待确认。
- 用户已确认的`phishing-url-operation-prc`下线决策以DEC-004为准；`log_compress`不原样迁移的方向保留，但不能丢弃保留消费者所需的加工语义。
