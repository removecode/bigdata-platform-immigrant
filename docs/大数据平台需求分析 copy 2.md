## 1. 摘要（致平台建设方）

### 1.1 现状

| 项 | 事实 |
|----|------|
| 运营固定查询 | **23 条**，全部 **手工（18）或临时脚本（5）**，无统一入口 |
| 日批依赖 | **19/23** 依赖「昨日审计/统计类数据」产出后才能查 |
| 架构 | 新旧两套数据并存；四类威胁指标（MD5/域名/URL/IP）**任一侧都不完整** |
| 保障投入 | 可归大数据平台投入约 **129.5h**，大量用于排障与保障 |
| 基础设施 | 2026 年 5–6 月磁盘拔插 **8/10 次**；曾 **任务全停**；换盘处置 **14.5h+** |

### 1.2 核心矛盾

不是缺少大数据平台，而是使用方日常面临：**能不能查、几点能查、查多久、挂了知不知道、该查哪类数据**——长期无统一答案。

### 1.3 我们要求的三大类能力

| 能力 | 使用方一句话 |
|------|-------------|
| **能查** | 按业务场景查，不靠每人维护 SQL |
| **早知道** | 数据未就绪、任务失败时，运营与运维同步知晓 |
| **少手工** | 高频场景（尤其 3 条/天热度、8 条/周主探）减少重复劳动 |

### 1.4 分期与硬指标（摘要）

| 阶段 | 范围 | 硬指标（摘选） |
|------|------|---------------|
| **一期** | **19/23** 场景统一可用 | 09:00 前昨日审计/统计类可查；失败日 **100%** 场景提示；近一月查询 P95 **≤15min** |
| **二期** | **23/23** 场景 + 高频自动化 | 近一月 P95 **≤10min**；手工占比 **≤22%**；高频自动 **≥8** 条 |

## 2. 使用方与当前使用情况

### 2.1 角色

| 角色 | 日常在平台上的工作 |
|------|-------------------|
| **运营** | 鉴定/主探/沙箱/合规日志查询，hash/IP/域名热度，处理量与时延分析 |
| **运维** | 保障日批数据按时可用；处理「查不到数」；磁盘等重大故障后恢复与告知 |

### 2.2 运营：23 条场景总览

| 维度 | 现状 |
|------|------|
| 时间范围 | **22/23** 按近一月；**#1** 按单日 |
| 按主题 | 文件/hash **8**；IP 主探 **8**；沙箱 **3**；URL/域名合规 **3**；多引擎 **1** |
| 按频次 | 多次/天 **3**（#16–18）；多次/周 **8**；多次/月 **8**；1 次/月 **4** |

逐条登记见 **附录 A**。

### 2.3 运维：当前保障方式

| 维度 | 现状 |
|------|------|
| 工作日节奏 | 凌晨前后产出「昨日」数据；**上午 9 点后**运营集中查数 |
| 就绪差异 | 审计/统计类较早；**IP/域名热度**（#17、#18）依赖更晚就绪的数据 |
| 故障发现 | 任务是否成功需多处查看；问题常到**使用时**才暴露 |
| 协作 | 运营「查不到数」报障信息不全，运维重复排查 |

### 2.4 典型故障对使用方的影响

| 事件 | 使用方影响 | 出处 |
|------|-----------|------|
| 日批未成功 | 19 条场景当日无法办公或空跑 | xlsx 依赖链 |
| 5/25 任务全停 | 全平台查数中断 | 换盘文档关联说明 |
| 5–6 月频繁换盘 | 运维 **14.5h+** 处置；数据可用性不确定 | 换盘文档 |
| 分区类问题未提前发现 | 晚间或次日查数才失败 | `DATA_FLOW.md` |

### 2.5 现状体验基线（诚实声明）

| 项 | 说明 |
|----|------|
| 查询耗时 | **材料未系统统计**；使用方体感：近一月查询**常久等**，无统一超时与原因提示 |
| 下文 P 类指标 | 为**诉求目标**，非现网承诺值 |
| 基线建立 | 能力上线后首月，双方按 §5.5 清单**各抽测 10 次/类**登记现状 |

### 2.6 过渡期数据约束（非诉求，但影响验收）

平台迁移未完成，四类威胁指标**不能假设任意场景都有**：

| 类型 | 新数据体系 | 旧数据体系 |
|------|-----------|-----------|
| MD5 / 域名 | 有 | 有 |
| URL | **无** | 有 |
| IP | 有 | **无**（无 IP 宽表） |

**使用方要求：** 建设方对 23 条场景给出**书面「场景 → 官方数据类型/链路」**（附录 B 待确认列），避免使用方猜错。

## 3. 痛点与对建设方的含义

### 3.1 运营痛点

| # | 我们感受到的 | 对建设方的含义（要交付什么体验） |
|---|-------------|-------------------------------|
| O-1 | 无统一入口，每人维护 SQL | 提供**按场景**的查询能力，而非只开表权限 |
| O-2 | 不知道昨天数据能不能查 | 提供**就绪状态**（可查 / 不可查 + 原因） |
| O-3 | 不清楚该查哪类数据 | 每场景**标明官方链路**，过渡期书面确认 |
| O-4 | 查询久等无反馈 | **进度、超时、可读原因**（如缩小日期范围） |
| O-5 | 高频仍手工 | **一键/自动**覆盖多次/天、多次/周场景 |

### 3.2 运维痛点

| # | 我们感受到的 | 对建设方的含义 |
|---|-------------|---------------|
| Y-1 | 运营问「能不能查」要逐个核实 | **一屏**展示影响运营的数据产出状态 |
| Y-2 | 失败发现太晚 | **主动通知**运维（影响日批者 ≤15min） |
| Y-3 | 报障信息不全 | 提供**报障模板**（场景、日期、是否已看就绪） |
| Y-4 | 磁盘等重大故障后运营不知情 | **告知运营**哪些场景暂停、预计何时恢复 |
| Y-5 | 平台变更不知影响谁 | 变更前提供**受影响场景编号清单** |

### 3.3 优先级

```text
P0  O-2/O-3 + Y-1/Y-2  →  能查、查哪、失败早知道
P1  O-4/O-5 + Y-4      →  快、少手工、大故障有话术
P2  O-1 + Y-3/Y-5      →  统一入口、报障与变更可预期
```

## 5. 验收指标

> 由**使用方体验**度量；建设方自选手段达标。

### 5.1 数据就绪（D）

| 指标 | 含义 | 目标 | 关联场景 |
|------|------|------|---------|
| **D-1** | 昨日审计/统计类可供查询 | 每自然日 **09:00 前**可用 | #1–#15, #22–#23 等 **19 条** |
| **D-2** | 昨日审计/统计类产出完成 | **01:00 前**（供早班） | 同上 |
| **D-3** | 昨日 IP/域名热度可供查询 | 每自然日 **09:00 前**可用 | #17、#18 |
| **D-4** | 日批失败日运营侧提示 | **09:00 前**，19 条相关场景 **100%** 标「不可用」 | 同上 |
| **D-5** | 月级数据可用率 | 审计/统计类 **≥99%** 自然日（基线待建） | 二期 |

### 5.2 查询性能（P）

| 指标 | 适用场景（附录 A 序号） | 查询范围 | P50 | P95 | 抽测要求 |
|------|------------------------|---------|-----|-----|---------|
| **P-1** | #3–#15, #22–#23 等明细类 | 近一月 | ≤5 min | ≤15 min（二期 ≤10 min） | 首月各 **10 次** |
| **P-2** | #1 鉴定任务状态 | 单日 | ≤1 min | ≤3 min（二期 ≤2 min） | 首月 **10 次** |
| **P-3** | #16–#18 热度 | 近一月 | ≤3 min | ≤8 min | 首月各 **10 次** |
| **P-4** | #20、#21 处理量 | 近一月 | ≤2 min | ≤5 min | 首月各 **10 次** |
| **P-5** | 导出 | 单次 ≤10 万行 | — | ≤60 s | 抽测 5 次 |
| **P-6** | 并发 | — | — | ≥**3** 人同时查互不影响 | 压测 3 路 |

**P-0（基线）：** 上线前无统一测量；首月联合登记现状，再校准二期 P 指标。

**使用方要求：** 超过 P95 时须给出**可读原因或建议**（如缩小日期、数据未就绪），不得无反馈长时间等待。

### 5.3 可用性与协作（A）

| 指标 | 含义 | 一期 | 二期 |
|------|------|------|------|
| **A-1** | 统一入口场景覆盖 | **≥19/23** | **23/23** |
| **A-2** | 手工查询占比（现 **78%**） | **≤55%** | **≤22%** |
| **A-3** | 单次查询步骤（选场景→见结果） | **≤6** | **≤4** |
| **A-4** | 查错数据导致空跑 | 较首月 **↓50%** | 较基线 **↓80%** |
| **A-5** | 报障信息完整率 | **≥90%** | **100%** |
| **A-6** | 影响日批的失败通知运维 | **≤15 min** | 同左 |
| **A-7** | 高频一键/自动场景数 | **3**（#16–18） | **≥8**（含多次/周主探等） |
