# 大数据平台迁移流程图

**文档日期：** 2026-09-09  
**范围：** 三区迁移；新平台目前已有审计日志数据，旧压缩日志表及其下游加工后续需要替代或下线。

```mermaid
flowchart TD
    START([启动迁移]) --> SCOPE{业务范围是否确认}
    SCOPE -- 否 --> CONFIRM[业务方确认任务和中间表<br/>保留 / 替代 / 下线]
    CONFIRM --> SCOPE
    SCOPE -- 是 --> INFRA{三区基础能力是否就绪}

    INFRA -- 否 --> BUILD[补齐计算、存储、队列、网络和权限<br/>确认 MongoDB / Redis / Kafka / Prometheus]
    BUILD --> INFRA
    INFRA -- 是 --> BASE{基础数据是否就绪}

    BASE -- 否 --> PREP[补齐新审计表、统计表、历史数据<br/>固定数据截止点和维表快照]
    PREP --> BASE
    BASE -- 是 --> MAP[建立旧表到新表映射<br/>提取任务 SQL、参数、UDF 和依赖]

    MAP --> BATCH[批量只读试跑和新旧结果对账]
    BATCH --> RESULT{验证结果}

    RESULT -- 仅改连接或表名 --> DIRECT[修改数据源配置]
    RESULT -- 字段不一致 --> VIEW[建立字段映射或兼容视图]
    RESULT -- 逻辑或 UDF 不兼容 --> CODE[改造 SQL、UDF、调度或脚本]
    RESULT -- 缺表或外部依赖 --> BLOCK[补齐维表、数据库、权限或资源]
    RESULT -- 业务确认不再需要 --> RETIRE[进入下线清单]

    DIRECT --> RECHECK[重新批量验证]
    VIEW --> RECHECK
    CODE --> RECHECK
    BLOCK --> RECHECK
    RECHECK --> RESULT

    RESULT -- 查询及数据一致 --> TASKTYPE{任务依赖类型}

    TASKTYPE -- 直接读取审计或统计 --> READONLY[迁移审计查询、统计查询<br/>及直接消费者]
    TASKTYPE -- 依赖旧 DWB --> DIM[补齐 hashinfo、设备、信誉和标签维表]
    DIM --> MODEL[按需建设 MD5、URL、Domain 替代模型]
    MODEL --> DWBAPP[迁移 DWB 下游任务]

    READONLY --> SINK{是否写外部系统}
    DWBAPP --> SINK
    SINK -- 是 --> SHADOW[写入影子 MongoDB Collection、Redis Key<br/>Kafka Topic 或隔离指标]
    SINK -- 否 --> BIZ[业务结果验收]
    SHADOW --> BIZ

    BIZ --> PASS{技术和业务是否验收通过}
    PASS -- 否 --> FIX[登记差异、明确责任人并修复]
    FIX --> RECHECK
    PASS -- 是 --> CUT[分任务切换读取和调度]

    CUT --> WATCH[观察一个完整业务周期<br/>监控数据、耗时、告警和外部输出]
    WATCH --> STABLE{运行是否稳定}
    STABLE -- 否 --> ROLLBACK[回切旧平台并修复]
    ROLLBACK --> RECHECK
    STABLE -- 是 --> STOP[停止旧 log_compress 及相关调度]
    STOP --> ACCESS{确认旧表已无访问}
    ACCESS -- 否 --> TRACE[定位遗漏消费者并迁移]
    TRACE --> RECHECK
    ACCESS -- 是 --> ARCHIVE[归档历史数据并按审批删除旧表]
    RETIRE --> ARCHIVE
    ARCHIVE --> END([迁移完成])
```

## 关键数据依赖

```mermaid
flowchart LR
    AUD[新平台审计日志] --> AQ[审计查询]
    AUD --> FILTER[IP 段统计任务]
    IPREP[IP 信誉表] --> FILTER
    FILTER --> REDIS[三区 Redis]

    AUD --> PHISH[钓鱼 URL 运营任务]
    PHISH --> MONGO[三区 MongoDB]

    STATS[新平台统计日志] --> SQ[统计查询]
    STATS --> CIPD[产品资源监控]
    CIPD --> PROM[Prometheus]

    AUD --> MD5[MD5 替代模型]
    HASH[hashinfo + 设备维表] --> MD5

    AUD --> URL[URL 替代模型]
    URLREP[URL 信誉 + 设备维表] --> URL

    AUD --> DOMAIN[Domain 替代模型]
    DOMAINREP[域名信誉 + 标签 + 设备维表] --> DOMAIN

    DOMAIN --> DOMAINAPP[domain-hit / active-domain]
    MD5 --> MD5APP[black-ti-context / black-file-clean]
```

## 使用说明

- 主流程中的循环表示：验证失败后先按原因修复，再进入同一批量验证通路。
- 新平台只有审计日志时，可以先推进审计查询；统计分支必须等待统计日志或替代模型。
- 依赖 MongoDB、Redis 等外部系统的任务，查询验证通过后仍需完成影子输出验证。
- 中间表是否重建由消费者和业务用途决定；确认不再需要的表直接进入下线清单。
- 旧任务先停止调度并观察访问，最后才归档或删除旧表。
