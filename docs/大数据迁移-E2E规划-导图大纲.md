# 项目全景
- Hive → StarRocks业务迁移
  - 业务目标与成功标准
    - 总目标：业务连续、结果可信、时效达标地退出旧Hive依赖
      - [建议待业务确认] 不以部署完成或SQL能跑代替业务迁移完成
    - B1 保留业务持续可用
      - 情报生产、统计监控、报告/样本导出及同步链路按确认范围持续运行
      - 验收：实际业务读取与场景通过，切换影响在批准窗口内
      - [待确认] 关键业务分级、可接受中断与恢复时间
    - B2 业务数据正确且完整
      - 必要过滤、关联、聚合、更新删除语义不因换源丢失
      - 验收：输入到业务使用五层对账，关键差异无未解释项
      - [待确认] 关键指标、容差、历史范围及验收人
    - B3 业务时效与处理能力达标
      - 日批按业务截止时间完成，增量结果保持约定新鲜度
      - 验收：正常/峰值/补数窗口满足约定，不影响其他生产负载
      - [待确认] 时效SLA、吞吐、并发与资源基线
    - B4 完成范围内业务的迁移与旧依赖退出
      - 保留任务切流并观察通过，退役任务取得批准
      - 验收：无未披露的旧平台供数或业务读取依赖
      - 三区环境过渡访问需单列，不等于三区迁移完全完成
      - 平台全局下线由数据湖统筹，不由我方单独承诺
    - B5 控制重复建设与迁移成本
      - 不重建已取消压缩任务，不迁无用途模型
      - 验收：承接边界清楚，共享加工/验证复用，资源预算获批
      - [待测量] 试点后估工，不承诺未经测算的收益比例
  - 迁移范围与依赖
    - [已确认] 清单去重45项，不等于45项都需迁移
      - 平台数据接入6项：承接方逐项确认
      - 平台内加工2项：只保留必要业务结果
      - 业务消费与同步23项：含2项暂归类
      - 其余14项：旁路7、维护2、退役相关5
    - 消费任务按主要输入细分
      - 原始日志7项：含SODL接入日志
      - 压缩日志3项：改读原始表，保留必要口径
      - 中间表7项：先落实等价结果
      - 业务表/维表4项：独立核实生产者
      - 层级待确认2项：yara与sp任务需补SQL
    - [已确认] audit先迁、stat后迁；新平台无压缩表及中间表
      - [待确认] 字段、历史、完整截止点及可用性验收
      - SODL与Mongo接入数据不默认已经交付
    - [材料] SODL接入与加工是两个环节
      - ClickHouse → sodl_ods_info → Hive接入日志
      - 六张：dns、endpoint_security、http、network_security、sip_iocstat、url
      - 接入日志与维表 → sodl_dwb_info → 四类DWB
      - sodl_ods_info_new的现网版本关系待核实
    - [材料] Mongo → 平台基础数据
      - sync-mongo2hive-job：hashinfo全量与增量
      - datax-server：资产、云情报IP/域名目录，实际配置待补
      - 不将信誉、设备等所有表默认归给DataX
  - 前期准备与确认
    - 数据湖交付
      - 每表目标名称、字段、类型、时间和过滤规则
      - 历史范围、增量/删除、补数和就绪信号
      - 交付负责人、日期、故障与变更通知
    - 业务确认
      - 任务和中间结果保留/替代/退役
      - 业务键、聚合口径、时效、允许差异
      - 实际读取者、验收人和切流窗口
    - 环境与资源
      - [已确认] 三区部分Mongo缺失
      - 网络、账号、索引、TTL、容量及恢复能力
      - 影子目标与生产隔离，双跑/对账/补数资源
    - 测试环境具备E2E验收能力
      - 覆盖输入数据 → 必要中间加工 → 真实任务 → 隔离输出 → 实际业务读取
      - 新旧可比窗口、维表版本与可重置的目标初始状态
      - Mongo/Redis/Kafka及适用文件、指标、外部接口均可联通和读回
      - 测试数据按权限脱敏，所有写入与业务副作用隔离
      - 支持重试、补数、故障恢复及回退演练，日志和报告可追溯
      - 放行：按本批依赖完成环境冒烟；模拟接口不能代替最终真实集成验收
    - 现网盘点
      - 部署SQL、代码、调度、参数和成功记录
      - 最长回看窗口、低频任务和隐藏依赖
  - 执行与批次
    - [建议] 按依赖就绪并行，不统一串行排队
      - audit/stat直接消费候选先试点
      - SODL、Mongo接入和必要模型同时准备
    - 最小改源优先
      - 连接/表名/字段映射 → 方言适配 → 必要逻辑改造
      - 禁止无差别全局字符串替换
    - 子任务验证，整任务验收
      - 混合来源分支可先验证，不可丢弃缺失分支
      - 原始明细替代压缩输入，性能需实测
    - 切流保护
      - 固定边界与迟到归属，防止新旧双写
      - 实例变化时同步验证业务读取路由
  - E2E验证
    - 输入：同完整窗口、版本、字段与更新删除
    - 中间加工：关联、去重、聚合与完整发布
    - 查询转换：应选数据与应写结果
    - 目标读回
      - Mongo：业务键、文档、upsert、删除和失败恢复
      - Redis：Key、结构、值、TTL和旧Key清理
      - Kafka：消息键、内容、重复、分区顺序及下游效果
      - 文件/SCP/指标：内容、完整发布、接收和实际使用
    - 业务使用：真实接口、报表、规则和时效
    - 正常/空结果/迟到/重跑/部分失败/补数/回退
  - 风险与耗时
    - 等待时间：共享输入、三区环境、业务与承接决策
    - 人工时间：差异定位、DWB适配、状态型输出恢复
    - 运行时间：历史回填、增量追平、规模验证
    - 业务周期：切流窗口、观察与低频覆盖
    - [判断] SQL改造不一定是最长项；需试点测量
  - 提效与项目推进
    - 批量自动化迁移能力建设
      - [计划能力，尚未实现] 任务清单、依赖图及迁移配置驱动
      - 自动预检 → 生成适配配置/候选SQL → 测试部署 → 对账与目标读回
      - 按输入/中间结果就绪信号编排批次，下游不越过依赖
      - 模板适配自动化，复杂SQL/UDF/模型改造进入人工评审队列
      - 产出版本化发布包、差异报告、失败任务及补偿清单
      - 审批后按批发布/切流，失败暂停相关依赖分支
      - 幂等、限并发、断点续跑；外部副作用不可盲目重试
      - 先代表任务证明工具可靠，再扩大覆盖
    - 共用映射、批量对账和目标读回工具
    - 固定窗口，共享输入问题集中定位
    - 提前确认去留与真实历史范围
    - 技术负责人 + 业务验收人 + 日期 + 证据
    - 分报输入就绪/查询通过/目标通过/已切流/观察完成
    - [待执行] 尚未现网验证、切流或取得各方承诺
  - 项目里程碑总览
    - M0 范围及业务目标基线确认，对应G0
    - M1 首批数据与环境验收就绪，对应G1
    - M2 代表链路E2E试点通过，对应G2/G3
    - M3 首批生产切流验收，对应G4
    - M4 确认保留范围分批切流完成，逐批通过G1-G4
    - M5 业务观察与验收完成，对应G5业务部分
    - M6 我方旧依赖退出确认，对应G5退出部分
    - 日期与具体签字人待确认；详细交付物见里程碑画布

# 风险与提效
- E2E风险、耗时与控制
  - 输入交付风险｜跨团队等待
    - SODL、hashinfo、维表或历史范围缺失
    - 后果：多个保留消费者同时被阻塞
    - 提效：逐表交付单，按受影响范围优先协调
    - 责任：数据湖/接入承接方；具名到人待落实
    - 放行：可访问、完整窗口、字段及更新规则通过验收
  - 业务与模型决策风险｜等待 + 返工
    - 无用模型被重建，或仍有消费者却取消逻辑
    - 提效：先确认用途；共享必要逻辑统一实现
    - 责任：业务验收人 + 模型负责人
    - 放行：去留签字、替代口径和承接方明确
  - 数据差异风险｜可能最耗人工
    - 迟到、时间窗口、维表快照或SQL版本不一致
    - 后果：每轮差异变化，反复无效重跑
    - 提效：固定输入版本，按输入到输出逐层定位
    - 责任：数据质量 + 任务开发 + 业务
    - 放行：关键差异解释闭环，独立业务样例正确
  - SQL与性能风险｜开发 + 运行
    - 函数、类型、JSON、时间及聚合语义不等价
    - 原始明细扫描、双跑、补数竞争生产资源
    - 提效：代表试点、执行计划、限并发后逐步放量
    - 责任：任务开发 + 平台资源方
    - 放行：结果正确，正常及峰值窗口满足约定
  - 目标状态风险｜联调 + 恢复
    - SQL正确但漏更新、旧数据未删或TTL错误
    - Kafka重复消息触发真实业务副作用
    - 提效：已知初始状态、隔离写入、共用读回工具
    - 责任：任务开发 + DBA + 下游负责人
    - 放行：更新/删除/重试/补数与业务读取均通过
  - 历史与增量风险｜机器运行时间
    - 历史不足、全量增量衔接漏数、积压追不平
    - 提效：按需求回填，分片检查点，测有效吞吐
    - 不能擅自缩短回看、补数、合规或恢复范围
    - 责任：数据湖/接入方 + 业务
    - 放行：所需历史具备，增量延迟达标且可持续
  - 切流与回退风险｜跨系统协调
    - 新旧双写、残留实例、迟到与边界归属不清
    - 新实例写对但业务仍读旧实例
    - 提效：单写者、边界清单、读取者同步验证
    - 责任：运维 + 任务与下游负责人
    - 放行：恢复/重建/补偿演练，不能只回切代码
  - 观察与退出风险｜业务周期
    - 低频任务漏验，共享接入或log_compress提前停止
    - 提效：提前定周期和签字人，先停调度后退役
    - 责任：项目推动者 + 数据湖 + 业务
    - 放行：无保留消费者或新平台中转依赖，保留期获批
  - 工期与提效边界
    - [待测量] 不承诺固定人日与收益比例
    - 等待时间、人工时间、运行时间分别记录
    - 首次通过率、重跑轮次、阻塞天数、吞吐与积压
    - 不删依赖、不放宽关键差异、不省目标与业务验证

# 依赖与放行
- 迁移路径与验收关口
  - 关口序列：G0 → G1 → G2 → G3 → G4 → G5
    - G0 范围：保留决定、SQL版本、负责人、用途明确
    - G1 输入：所需数据、权限、历史和时效验收
    - G2 查询：最小适配、同窗口对账、性能通过
    - G3 E2E：影子写入、读回、业务用例及恢复演练
    - G4 切流：单写者、边界、读取路由和首批对账
    - G5 观察退出：业务周期达标，旧依赖可退出
    - 每条分支独立推进；准备工作并行，关口不能跳过
  - 路径A：audit压缩消费 → 原始表 → Redis
    - 候选：filter-layout-ip-seg-stat-prc
    - 前置：audit映射 + IP信誉 + Redis与实际读取者
    - 01 复现必要压缩字段映射及过滤
    - 02 同窗口查询对账与性能验证
    - 03 影子Redis写入与TTL/更新验证
    - 04 固定边界切流，验证实际业务读取
    - 风险：audit已迁不代表整条链路就绪
  - 路径B：SODL → 必要DWB → Mongo业务
    - 示例：domain-heat-stats-cron-job，保留待确认
    - 前置：业务保留 + 所需SODL日志/维表 + 模型承接 + Mongo
    - 01 接入数据验收
    - 02 Domain等价结果与完整发布验证
    - 03 消费查询及影子Mongo状态验证
    - 04 实际业务读取通过后切流观察
    - 风险：不能用audit替代SODL，不能用明细直接替代聚合结果
  - 路径C：Mongo → hashinfo → 文件导出
    - 示例：cert-app-samplesync-job
    - 前置：源Mongo与同步方案 + business_data等其他输入
    - 01 快照和增量衔接、更新删除及恢复验证
    - 02 新平台hashinfo业务字段与时效验收
    - 03 查询、文件内容及完整发布验证
    - 04 实际接收使用验证；国家版另验SCP
    - 风险：一个消费者迁完不能停止共享hashinfo接入
  - 可并行的工作
    - SQL盘点与映射、数据交付、业务决策同时开始
    - 影子目标和回退方案不等开发完成才准备
    - stat独立候选：cipd-product-resource-monitor-prc
    - 目标缺失可先只读验证，但G3不能标通过
  - 切流红线
    - 输入不完整或关键差异未解释：不放行
    - 写入所有权不明或真实读取者未验：不放行
    - 无恢复/补偿能力：不放行
    - 旧平台仍供数：过渡依赖，不算完全退出
  - 推动者首轮行动
    - 锁定共享数据交付负责人和日期
    - 业务确认去留、口径、验收人及窗口
    - 补DataX配置、yara与sp实际SQL
    - 落实三区数据库、影子环境及资源
    - 用代表任务试点证据估算后续工期

# 业务目标与里程碑
- 从业务目标到项目验收
  - 基线与排期原则
    - [状态] 以下均为建议里程碑，不代表已达成或已获批准
    - 目标日期、实际日期、责任人、签字人、证据与阻塞项逐项登记
    - M0锁范围与成功标准，M2试点后校准整体排期
    - 各批独立循环M1-M3；后续准备不等待首批完成
    - 首批完成不等于全量完成，业务验收不等于平台全局下线
  - M0 范围与业务目标基线确认
    - 支撑：B1连续性、B2正确性、B3时效、B4退出、B5成本
    - 对应关口：G0；目标日期待确认
    - 交付：45项逐项处置、SQL级依赖、保留模型与业务读取者清单
    - 交付：关键业务等级、验收指标/容差、时效和恢复目标
    - 交付：数据湖/业务/我方责任与预算基线
    - 完成标准：首批去留、具体负责人和业务验收人明确
    - 全量待决项有截止日期，不能默认为退役
    - 牵头：项目推动者；确认：业务与数据湖责任方
  - M1 首批输入与环境验收就绪
    - 支撑：B2正确性、B3时效；对应G1
    - 前置：首批M0，数据湖与环境交付可以提前并行
    - 交付：表/字段映射、历史与完整窗口、输入验收报告
    - 交付：影子输出、权限/网络、资源配额及恢复条件
    - 交付：可E2E验收的测试环境与冒烟报告，覆盖本批输入到实际业务读取
    - 交付：可比数据、目标初始状态、写入隔离、观测与恢复演练能力
    - 完成标准：首批全部必要输入和端到端验证环境可用
    - SQL可先验证，但目标缺失不能标记M1完整就绪
    - 牵头：数据湖/DBA/任务方；确认：首批技术负责人
    - 目标日期待确认，按每批分别记录
  - M2 代表链路E2E试点通过
    - 支撑：B1/B2/B3/B5；对应G2/G3
    - 前置：试点所需M1及已确认验收口径
    - 交付：输入、加工、查询、目标、业务五层适用验证报告
    - 交付：正常/峰值与重试补数测试、恢复或补偿演练
    - 交付：批量验证模板、真实改造分类及后续工期估算
    - 交付：批量自动迁移试点报告，覆盖预检、测试部署、验收和发布包生成
    - 工具验收：故意缺依赖/错数据可拦截，失败可定位，重跑不重复产生副作用
    - 完成标准：代表任务关键差异闭环，性能和恢复达标
    - 覆盖边界：试点成功不代表全部任务已通过
    - 牵头：任务开发/测试；签字：业务与技术负责人
    - 目标日期待确认；必要模型等复杂路径可另立试点
  - M3 首批生产切流验收
    - 支撑：B1连续性、B2正确性、B3时效；对应G4
    - 前置：首批M2或等效证据、业务窗口与切流批准
    - 交付：发布版本、单写者边界、位点/批次、备份与恢复单
    - 交付：首个完整生产批次对账、业务读取及监控记录
    - 完成标准：边界无未解释错漏，实际业务读取新结果
    - 非完成标准：仅部署成功或新目标中有数据
    - 牵头：发布/运维与任务方；签字：业务负责人
    - 目标日期随批准窗口确定；持续观察尚未结束
  - M4 确认保留范围分批切流完成
    - 支撑：B4迁移、B5成本；逐批满足G1-G4
    - 前置：各批相关依赖齐备并各自通过验证
    - 交付：全部确认保留任务切流记录与批准退役清单
    - 交付：混合来源、低频任务、三区目标及读取者覆盖矩阵
    - 完成标准：范围内无遗漏；待决任务须解决或获批调整范围
    - 过渡依赖单列为残留，不算已退出旧平台
    - 牵头：项目推动者；签字：各业务与技术责任人
    - 目标日期在试点和外部交付承诺后确定
  - M5 业务观察与验收完成
    - 支撑：B1连续性、B2正确性、B3时效；对应G5业务部分
    - 前置：相关批次已切流，可与其他批次迁移并行观察
    - 交付：约定周期的时效/差异/错误/业务指标报告
    - 交付：低频或周月任务覆盖、遗留问题处置与业务签字
    - 完成标准：关键业务目标达成，范围内观察与验收闭环
    - [待确认] 观察周期按业务确定，不能一律按单日通过
    - 牵头：业务/运维/数据质量；签字：业务验收人
    - 全量完成日期取最后一批观察及验收结束时间
  - M6 我方旧依赖退出确认
    - 支撑：B4退出、B5减少重复运行；对应G5退出部分
    - 前置：相关M5、旧消费者/中转供数核查、退役批准
    - 交付：无旧依赖证据、旧调度停用与观察、保留期和交接单
    - 完成标准：我方保留业务不再依赖旧接入/压缩/加工链路
    - 共享任务须所有相关消费者确认后才能停止
    - 不立即删除旧数据，不擅自宣布整个平台下线
    - 牵头：项目推动者/数据湖；签字：共享链路责任方
    - 目标日期在旧依赖核查和保留方案确定后锁定
